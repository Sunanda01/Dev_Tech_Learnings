# MongoDB Aggregation Pipeline

## 1. What is Aggregation?

MongoDB Aggregation is used to process, transform, filter,
group, calculate and reshape documents inside MongoDB.

## 2. What is an Aggregation Pipeline?

An aggregation pipeline is a sequence of stages where the
output of one stage becomes the input of the next stage.

Example:

Collection
→ $match
→ $group
→ $sort
→ $limit
→ Result

## 3. Why Aggregation?

Instead of fetching a large number of documents to the
application and processing them there, aggregation allows
MongoDB to perform the processing close to the data.

Benefits:
- Less network transfer
- Less application memory usage
- Less application-side processing
- Less application code
- Efficient data transformation

## 4. What was used before?

Common approaches included:

1. Basic MongoDB queries such as find(), sort(), skip(),
   limit(), etc.

2. Application-side processing:
   MongoDB → Application → filter/group/sort/calculate

3. MapReduce for server-side aggregation workloads.

Aggregation Pipeline became the preferred approach for many
common aggregation tasks.

## 5. Aggregation vs find()

find():
- Mainly retrieves/filter documents.
- Best for simple CRUD/read operations.

aggregate():
- Processes and transforms documents.
- Supports filtering, grouping, calculations, joins,
  array processing, sorting, reshaping, etc.

Aggregation does NOT replace find(). Simple queries should
still use normal MongoDB queries.

## 6. Core Pipeline Stages

- $match      → filter documents
- $project    → select/reshape fields
- $set        → add/modify fields
- $group      → group and calculate
- $sort       → sort documents
- $limit      → limit results
- $skip       → skip documents
- $count      → count documents
- $unwind     → flatten array elements
- $lookup     → join with another collection
- $facet      → run multiple pipelines on the same input

## 6.9 $unwind

### What?
Deconstructs an array field and outputs one document
for each element of the array.

### Industry Usage

🔥🔥🔥🔥🔥 Very High

Used for:
- E-commerce order items
- Product reviews
- Comments
- Tags
- User addresses
- Nested arrays
- Analytics
- Processing $lookup results

### Basic Syntax
```js
{
  $unwind: "$items"
}
```

### Important Options
1. preserveNullAndEmptyArrays : Preserves the document when the array is null, missing, or empty.

Syntax
```js
{
  $unwind: {
    path: "$items",
    preserveNullAndEmptyArrays: true
  }
}
```
Default is false, use true when documents without array values
should also remain in the pipeline.

2. includeArrayIndex : Stores the original array element index in a new field.

Syntax
```js
{
  $unwind: {
    path: "$items",
    includeArrayIndex: "itemIndex"
    preserveNullAndEmptyArrays: true
  }
}
```

## 6.10. $lookup

### What?

Performs a left outer join between the current collection
and another collection and stores the matching documents
in an array field.

### Industry Usage

🔥🔥🔥🔥🔥 Very High

Used for:
- Orders → Users
- Orders → Products
- Posts → Users
- Comments → Users
- Videos → Creators
- Products → Reviews
- Payments → Orders
- Referenced MongoDB documents

### Basic Syntax

```js
{
  $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "user"
  }
}
```

### Important Fields
- `from` → Target collection to join.
- `localField` → Field from the current collection used for matching.
- `foreignField` → Field from the target collection used for matching.
- `as` → Name of the output array containing matching documents.

### Pipeline Form of $lookup
Used when the join requires filtering, projection,
sorting, limiting, or more complex conditions.

### Syntax
```json
{
  $lookup: {
    from: "users",
    let: {
      uid: "$userId"
    },
    pipeline: [
      {
        $match: {
          $expr: {
            $eq: ["$_id", "$$uid"]
          }
        }
      }
    ],
    as: "user"
  }
}
```

- `pipeline` → Defines aggregation stages to execute on the joined collection.
- `let` → Defines variables using fields from the current document.
- `$expr` → Allows aggregation expressions inside $match.
- `$$variable` → References a variable defined using let.

## 6.11. $facet

### What?

Runs multiple independent aggregation pipelines on the
same input documents and returns the results together.

### Industry Usage

🔥🔥🔥🔥 High

Used for:
- Pagination + total count
- Search APIs
- E-commerce filters
- Dashboards
- Analytics
- Reports
- Multiple statistics
- Category/brand filters

### Basic Syntax

```js
{
  $facet: {
    facetName1: [
      // pipeline stages
    ],
    facetName2: [
      // pipeline stages
    ]
  }
}
```

- All facet pipelines receive the same input documents
that reach the $facet stage.
- Each facet pipeline works independently.
- `facetName` → Name of an independent pipeline and becomes
the corresponding field in the output document.
- `pipeline` → Array of aggregation stages executed for
that facet.

### facet vs multiple queries
$facet isn't automatically faster than multiple queries.
It depends on:
- Dataset size
- Number of facet pipelines
- Complexity of each pipeline
- Index usage
- Amount of data processed
- MongoDB resources

### The correct interview answer is: 
$facet can reduce application-to-database round trips by producing multiple results from the same input set, but performance should be evaluated based on the actual workload.

## $bucket
### What?

Groups documents into explicitly defined ranges using
boundaries provided by the developer.

### Basic Syntax

```js
{
  $bucket: {
    groupBy: "$price",
    boundaries: [0, 10000, 20000, 50000],
    default: "Other",
    output: {
      count: {
        $sum: 1
      }
    }
  }
}
```

### Important Options

`groupBy` → Expression used to determine the bucket.

`boundaries` → Array defining the bucket boundaries.

`default` → Bucket for values that don't fit any defined range.

`output` → Accumulator expressions used to calculate
information for each bucket.

### Note
- Lower boundary is inclusive.
- Upper boundary is exclusive.

## $bucketAuto
### What?

Automatically determines bucket boundaries based on the
input data and the requested number of buckets.

### Basic Syntax
```js
{
  $bucketAuto: {
    groupBy: "$price",
    buckets: 5
  }
}
```
### Important Options

`groupBy` → Expression used to determine bucket placement.

`buckets` → Approximate number of buckets to create.

`output` → Accumulator expressions used to calculate
information for each bucket.

## 7.5 $setWindowFields

### What?

Performs calculations across a set of related documents
while keeping the original documents.

Used for running totals, rankings, moving averages,
previous/next values, and advanced analytics.

### Industry Usage

🔥🔥🔥🔥 High for analytics-heavy systems

Used for:
- Running totals
- Rankings
- Leaderboards
- Moving averages
- Previous/next record comparisons
- Time-series analytics
- Financial analytics
- Reports
- Business dashboards

### Basic Syntax

```js
{
  $setWindowFields: {
    partitionBy: "$userId",
    sortBy: {
      createdAt: 1
    },
    output: {
      runningTotal: {
        $sum: "$amount",
        window: {
          documents: [
            "unbounded",
            "current"
          ]
        }
      }
    }
  }
}
```
### Important Options

`partitionBy` → Divides documents into independent groups
for window calculations.

`sortBy` → Defines the order of documents inside each
partition.

`output` → Defines the calculated fields produced by the
window operation.

`window` → Defines which documents around the current
document are included in the calculation.

`Running Total` → Calculates a cumulative value from the beginning of the partition up to the current document.

### Syntax
``` json
{
  $setWindowFields: {
    partitionBy: "$userId",
    sortBy: {
      createdAt: 1
    },
    output: {
      runningTotal: {
        $sum: "$amount",
        window: {
          documents: [
            "unbounded",
            "current"
          ]
        }
      }
    }
  }
}
```

`Ranking` → Assigns a rank to documents based on the specified sort
order.

### Syntax
``` json
{
  $setWindowFields: {
    sortBy: {
      score: -1
    },
    output: {
      rank: {
        $rank: {}
      }
    }
  }
}
```

### $rank vs $denseRank

`$rank` → Ties create gaps in ranking.

`$denseRank` → Ties do not create gaps.

`Average` → Calculates an average over a moving window of documents.

### Syntax
``` json
{
  $setWindowFields: {
    sortBy: {
      date: 1
    },
    output: {
      movingAverage: {
        $avg: "$sales",
        window: {
          documents: [
            -2,
            "current"
          ]
        }
      }
    }
  }
}
```

#### [-2, current] → Current document + previous 2 documents.

#### Useful for:

- Sales trends
- Stock/financial analysis
- Time-series analytics
- Performance monitoring

`Previous Value` → Retrieves a value from a previous or future document in the ordered window.

### Syntax
``` json
{
  $setWindowFields: {
    sortBy: {
      date: 1
    },
    output: {
      previousSales: {
        $shift: {
          output: "$sales",
          by: -1
        }
      }
    }
  }
}
```

#### Useful for comparing:

- Today vs yesterday
- Current month vs previous month
- Current score vs previous score

### $setWindowFields vs $group

`$group` → Combines documents and usually produces fewer
documents.

`$setWindowFields` → Calculates across documents while
retaining the original documents.

``` bash
$group:

10 documents
     ↓
$group
     ↓
1 or fewer grouped documents


$setWindowFields:

10 documents
     ↓
$setWindowFields
     ↓
10 documents
+
calculated fields
```

## 8.1 $merge

### What?

Writes the results of an aggregation pipeline into a
target collection.

Unlike most aggregation stages, `$merge` persists the
aggregation result.

### Industry Usage

🔥🔥🔥 Medium–High

Used for:
- Pre-computed analytics
- Materialized views
- Reporting collections
- Data synchronization
- ETL/data processing
- Summary collections
- Batch processing

### Basic Syntax

```js
{
  $merge: {
    into: "targetCollection"
  }
}
```

### Important Options

`into` → Target collection where aggregation results are written.

`on` → Field(s) used to identify matching documents in the target collection.

`whenMatched` → Defines what happens when a matching document exists.

`whenNotMatched` → Defines what happens when no matching document exists.

### Important whenMatched Values

`replace` → Replace the existing document.

`merge` → Merge the aggregation result into the existing document.

`keepExisting` → Keep the existing target document unchanged.

`fail` → Stop the operation if a matching document is found.

### Important whenNotMatched Values

`insert` → Insert the aggregation result.

`discard` → Ignore the result.

`fail` → Stop the operation.

### Syntax
```js
{
  $merge: {
    into: "userSpendingSummary",
    on: "_id",
    whenMatched: "merge",
    whenNotMatched: "insert"
  }
}
```

### $merge vs $out

`$merge` → Updates/inserts/merges into an existing collection.

`$out` → Writes the aggregation result to a collection,
effectively replacing its contents.

## 8.4 $graphLookup

### What?

Performs a recursive search within a collection by
following relationships between documents.

Useful for hierarchical and graph-like data.

### Industry Usage

🔥🔥 Low–Medium

Used for:
- Employee/manager hierarchies
- Organization structures
- Category trees
- Parent/child relationships
- Dependency graphs
- Network traversal

### Basic Syntax

```js
{
  $graphLookup: {
    from: "employees",
    startWith: "$employeeId",
    connectFromField: "employeeId",
    connectToField: "managerId",
    as: "hierarchy"
  }
}
```

### Important Options

`from` → Collection to recursively search.

`startWith` → Starting value for the recursive traversal.

`connectFromField` → Field whose value is used to continue
the recursive traversal.

`connectToField` → Field matched against the recursive value.

`as` → Array field where discovered documents are stored.

`maxDepth` → Maximum recursion depth.

`depthField` → Field storing the recursion depth.

`restrictSearchWithMatch` → Additional filter applied
during recursive traversal.

### $lookup vs $graphLookup

`$lookup` → Non-recursive join.

`$graphLookup` → Recursive relationship traversal.

### $graphLookup vs $unwind

`$unwind` → Converts array elements into separate documents.

`$graphLookup` → Recursively follows relationships.

## 9.1 Accumulator Operators

### What?

Accumulators calculate values from multiple documents,
commonly inside `$group` and `$setWindowFields`.

### Industry Usage

🔥🔥🔥🔥🔥 Very High

Used for:
- Revenue calculations
- Order statistics
- User statistics
- Product analytics
- Reports
- Dashboards
- Business metrics
- Grouped analytics

### Important Accumulators

`$sum` → Calculates the sum of numeric values.

`$avg` → Calculates the average of numeric values.

`$min` → Returns the minimum value.

`$max` → Returns the maximum value.

`$first` → Returns the first value encountered.

`$last` → Returns the last value encountered.

`$push` → Collects values into an array, including duplicates.

`$addToSet` → Collects unique values into an array.

`$stdDevPop` → Calculates population standard deviation.

`$stdDevSamp` → Calculates sample standard deviation.


### $count Stage vs $sum: 1

`$count stage` → Counts documents after a pipeline stage.
```js
{
  $count: "total"
}
```

`$sum: 1` → Counts documents inside each $group.
```js
{
  $group: {
    _id: "$userId",
    count: {
      $sum: 1
    }
  }
}
```

### One thing to remember

```text
$sum       → Total
$avg       → Average
$min       → Smallest
$max       → Largest
$first     → First
$last      → Last
$push      → Array + duplicates
$addToSet  → Array + unique
```

## 9.2 Comparison Operators

### What?

Comparison operators compare two values and return
`true` or `false`.

Commonly used with `$match`, `$expr`, `$project`,
`$set`, `$cond`, and `$filter`.

### Industry Usage

🔥🔥🔥🔥🔥 Very High

Used for:
- Filtering records
- Price comparisons
- Range checks
- Status checks
- Conditional fields
- Array filtering
- Business rules
- Date comparisons

### Important Operators

`$eq` → Checks whether two values are equal.

`$ne` → Checks whether two values are not equal.

`$gt` → Checks whether the first value is greater than the second.

`$gte` → Checks whether the first value is greater than or equal to the second.

`$lt` → Checks whether the first value is less than the second.

`$lte` → Checks whether the first value is less than or equal to the second.

### Quick Reference

```text
$eq   → ==
$ne   → !=
$gt   → >
$gte  → >=
$lt   → <
$lte  → <=
```

### $match Query Syntax vs Expression Syntax

`Query operator:`
### Syntax
```js
{
  $match: {
    amount: {
      $gt: 1000
    }
  }
}
```

`Aggregation expression:`
### Syntax
```js
{
  $project: {
    isExpensive: {
      $gt: ["$amount", 1000]
    }
  }
}
```

`$expr` → $expr allows aggregation expressions to be used
inside $match.

### Example:
```js
{
  $match: {
    $expr: {
      $gt: ["$totalAmount", "$discountLimit"]
    }
  }
}
```
- Useful when comparing one field with another field.

Date operators extract, format, compare, manipulate, and
bucket Date values inside aggregation pipelines.

### Industry Usage

🔥🔥🔥🔥 Very High

Used for:
- Orders
- Payments
- Logs
- Reports
- Analytics
- Subscriptions
- SLA calculations
- Time-based filtering
- Daily/monthly statistics

### Important Operators

`$year` → Returns the year from a date.

`$month` → Returns the month number from a date.

`$dayOfMonth` → Returns the day of the month.

`$dayOfWeek` → Returns the day of the week.

`$hour` → Returns the hour from a date.

`$dateToString` → Converts a Date into a formatted string.

`$dateFromString` → Converts a date string into a MongoDB Date.

`$dateDiff` → Calculates the difference between two dates.

`$dateAdd` → Adds a time amount to a date.

`$dateSubtract` → Subtracts a time amount from a date.

`$dateTrunc` → Truncates a date into a time bucket.

## 10. Industry Patterns
| Requirement            | Pattern                      |
| ---------------------- | ---------------------------- |
| Page results           | `$skip` + `$limit`           |
| Large-scale pagination | Cursor/range pagination      |
| Top 10 overall         | `$sort` + `$limit`           |
| Top N per group        | `$setWindowFields` / ranking |
| Join collections       | `$lookup`                    |
| Join + single result   | `$lookup` + `$unwind`        |
| Revenue                | `$group` + `$sum`            |
| Dashboard metrics      | `$facet`                     |
| Nested array analytics | `$unwind`                    |
| Filter nested array    | `$filter`                    |
| Transform array        | `$map`                       |
| Running total          | `$setWindowFields`           |
| Ranking                | `$setWindowFields`           |


## 11. Performance & Optimization

### What?

Aggregation performance optimization focuses on reducing the
amount of data processed, using appropriate indexes,
optimizing stage order, and analyzing query execution.

### Industry Usage

🔥🔥🔥🔥🔥 Extremely High

## 11.1 `$match` Early

### Definition

Filter documents as early as possible to reduce the data
processed by later stages.

### Example

```js
[
  {
    $match: {
      status: "completed"
    }
  },
  {
    $group: {
      _id: null,
      total: {
        $sum: "$amount"
      }
    }
  }
]
```
---

## 11.2 Indexes
### Definition

Indexes allow MongoDB to find matching documents more
efficiently instead of scanning the entire collection.

### Syntax
```json
db.orders.createIndex({
  status: 1
})
```
Aggregation does not eliminate the need for indexes. 

---

## 11.3 explain()
### Definition
Shows how MongoDB plans and executes a query.

### Syntax
```json
db.orders.explain("executionStats").aggregate([
  {
    $match: {
      status: "completed"
    }
  }
])
```

### Important Metrics

`executionTimeMillis` → Query execution time.

`totalDocsExamined` → Number of documents examined.

`totalKeysExamined` → Number of index keys examined.

`nReturned` → Number of returned documents.

### IXSCAN vs COLLSCAN

`IXSCAN` → MongoDB is scanning an index.

`COLLSCAN` → MongoDB is scanning the collection.

---

## 11.4 $sort Performance

### Sorting a large dataset can be expensive.

### Example:
```json
{
  $sort: {
    createdAt: -1
  }
}
```

An appropriate index can sometimes allow MongoDB to read
documents in the required order without a large in-memory sort.

---

## 11.5 $match + $sort + $limit

### Common backend pattern:
```json
[
  {
    $match: {
      status: "completed"
    }
  },
  {
    $sort: {
      createdAt: -1
    }
  },
  {
    $limit: 20
  }
]
```

Possible compound index:
```json
db.orders.createIndex({
  status: 1,
  createdAt: -1
})
```

Always verify the actual workload with explain().

---

## 11.6 $lookup Performance
### Rule

The fields used to match documents in the foreign collection
should be appropriately indexed.

### Example:
```json
{
  $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "user"
  }
}
```
For custom foreign fields, consider an index when the
workload benefits from it.

---

## 11.7 Filter Before $lookup

### Prefer:
```json
$match
   ↓
$lookup
```

instead of:
```json
$lookup
   ↓
$match
```

when the filter can reduce the documents entering the join.

---

## 11.8 $unwind Can Explode Data

$unwind converts one document into multiple documents.

```bash
1 document
   ↓
$unwind
   ↓
N documents
```

- Large arrays can therefore create huge intermediate datasets.
- Consider $filter, $map, or other array operators when
you don't actually need separate documents.

---

## 11.9 $facet Performance

$facet runs multiple sub-pipelines on the same input.

### Useful for dashboards:
```json
{
  $facet: {
    stats: [...],
    revenue: [...],
    orders: [...]
  }
}
```
- Filter before $facet when all branches can benefit
---

## 11.10 Pagination Performance

### Offset pagination:

### $skip + $limit

- Can become expensive for deep pages.

- Large-scale systems commonly consider:

```json
Cursor
   ↓
Range query
   ↓
$limit
```

### Example:
```json
{
  $match: {
    createdAt: {
      $lt: lastSeenCreatedAt
    }
  }
}
```

---

## 11.11 Covered Queries
### Definition

A query is covered when MongoDB can satisfy the required
query and projection using only an index without fetching
the full documents.

### Example:
```json
db.users.createIndex({
  email: 1,
  name: 1
})
```
---
## 11.12 Aggregation Memory

### Stages such as:
- $sort
- $group
- $setWindowFields
- $facet

can require substantial memory for large datasets.
MongoDB supports disk use for eligible aggregation operations:
```json
db.orders.aggregate(
  [
    // pipeline
  ],
  {
    allowDiskUse: true
  }
)
```

**allowDiskUse is not a replacement for proper optimization.**

---

## 11.13 Index Design

Design indexes around actual query patterns.

### Example:
``` json
[
  {
    $match: {
      userId: 123,
      status: "completed"
    }
  },
  {
    $sort: {
      createdAt: -1
    }
  },
  {
    $limit: 20
  }
]
```
### Possible index:
```json
db.orders.createIndex({
  userId: 1,
  status: 1,
  createdAt: -1
})
```

**Always verify index effectiveness using explain().**

---

## 11.14 Index Trade-offs

Indexes can improve reads but increase:

- Write cost
- Storage usage
- Index maintenance
- Memory requirements

**Therefore, don't create indexes without considering
actual query patterns.**

---

## 11.15 Denormalization
### Definition

Stores frequently-read related data directly inside a
document to reduce expensive joins.

### Example:
```json
{
  orderId: 123,
  userId: 10,
  userName: "Sunanda"
}
```
instead of always performing:

```json
orders
   ↓
$lookup
   ↓
users
```

### Trade-off
```json
Denormalization
     ↓
Faster reads
     +
More complicated updates
```
